“继续对话与执行上下文”已完成、自测并审核。下一阶段建议接入本地 AI，先提供受平台授权约束的工具调用入口。下面后续阶段仍是开发建议。

## A 当前已经有什么

- 本地登录、项目角色和对象级授权。
- 沙箱创建、续期、销毁、文件操作、命令与日志。
- 经平台授权的 HTTP GET 接口验证。
- 用户逻辑 Namespace、工作区和独立 PVC。
- 对话引用登记、绑定历史和原工作区定位。
- 数据长期保留、归档和计算实例独占。

依据：internal/interfaces/router/router.go 的实际路由，以及 design/workspace-phase1.md。

## B 已完成：继续对话与执行上下文

场景：几天后继续原对话，自动定位代码目录并准备运行环境。

增加一个继续入口。平台核验当前用户、项目、对话和工作区，再复用可用实例或创建新实例。工作区被占用、实例状态不确定或存储异常时，返回明确状态。

生成 RunContext，固定操作者、对话、工作区、绑定版本、实例和挂载代次。文件、命令和日志接口检查这个上下文。上下文 ID 不能代替用户认证。

将准备过程保存为持久任务。创建超时先核对结果，不能直接重放创建。多副本领取与重启恢复需要单独验证。

验收：停止旧实例后继续原对话，读取同一文件；并发继续只产生一个实例；迟到请求不能操作新绑定的目录。

## C 下一阶段：本地 AI 工具接入

场景：本地 AI 上传代码、启动应用、查日志并修改代码。

提供经过平台认证和授权的工具接口。先支持继续对话、读写文件、执行命令、增量日志和接口验证。随后封装平台自己的 MCP 适配器。

AI 请求携带当前用户身份，不向客户端发放共享 OpenSandbox 管理密钥。审计关联 actor、conversationId、workspaceId、runContextId 和操作结果。

验收：用两个用户的凭证测试同一资源，跨用户请求被拒绝；运行一个小应用并完成修改后的再次验证。

## D 第三优先：应用运行管理

场景：代码保留后，一键重新启动应用并查看运行状态。

保存工作目录、启动命令、应用端口和健康检查路径。记录进程或命令 ID、启动时间、退出状态和日志游标。

提供启动、停止、重启和健康检查入口。凭证使用受控秘密引用，不直接写入可浏览的运行配置。

验收：启动失败能定位原因；重建沙箱后可以用同一运行配置启动应用。依赖通过镜像或受控安装步骤恢复。

## E 公司试用前：认证与数据保护

接入公司 OIDC：身份映射、平台会话、账号停用和项目授权。需要公司提供 IdP 地址、客户端登记与回调约定。

关闭普通用户绕过平台直接访问 OpenSandbox 的入口。平台上游凭证、网络入口和最小 RBAC 一起核对。

补备份和恢复演练。当前 local-path 工作区保留不等于跨节点容灾。

回收站可独立开发。永久清除应等待保留策略、备份责任和恢复规则确认，不能默认启动自动删除。

## F 最后：镜像构建与发布

场景：验证通过的代码生成镜像，再交付线上运行。

从固定代码版本或受控快照构建 OCI 镜像。构建进程与开发沙箱分离，推送镜像仓库，记录摘要、来源和构建日志。

把镜像摘要交给现有发布平台。开发环境的 PVC 文件、临时进程和系统修改不能自动等同于可复现镜像。

验收：在没有开发 PVC 的新环境中，镜像仍能独立启动并通过健康检查。

## G 推荐本轮范围

B 已完成，代码和测试见 conversation-runtime-phase2.md。下一轮建议只实现 C：以当前用户身份调用平台 API 的 MCP 适配器，支持继续对话、工作区文件读写、命令、日志和 HTTP 验证，并用两个用户验证权限隔离。

默认不在本轮加入聊天消息保存、全功能终端、自动发布或 PVC 永久清除。后续阶段分别设计验收。

以上顺序依据项目自身目标和现有实现，没有把已确认的工作区绑定视为完整 AI 执行调度。
