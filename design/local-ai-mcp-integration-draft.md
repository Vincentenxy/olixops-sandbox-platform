平台负责身份、授权、工作区和运行环境。本地 AI 负责代码开发。
建议新增平台 MCP 入口、本地项目绑定和显式文件同步。

## A 结论与职责

```flow LR
本地AI工具 -> 平台MCP入口: 用户授权
平台MCP入口 -> 统一业务与权限服务: 工具调用
平台控制台 -> 统一业务与权限服务: 管理操作
统一业务与权限服务 -> OpenSandbox: 平台服务凭据
OpenSandbox -> 沙箱实例: 计算与执行
沙箱实例 -> [(工作区PVC)]: 挂载持久数据
```

本地保留 IDE、AI 对话、代码仓库和开发流程。
平台管理资源、权限、配额、准备任务与操作审计。
MCP 只是一个工具入口。它不能替代业务授权。
平台可以记录外部会话引用，无需保存聊天正文。

推荐远程 Streamable HTTP MCP 作为公司统一入口。
本地小工具负责目录绑定、凭证保管和文件传输。
不支持远程入口的客户端可用本地 stdio 适配器。
两种入口最终都经过平台权限检查。

[MCP 官方传输定义](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports)

## B 长期绑定工作区，每次执行固定实例

| 对象 | 建议关联 | 生命周期 |
|---|---|---|
| 本地项目目录 | 平台地址、登录配置、projectId、workspaceId | 跨 IDE 重启保留 |
| 本地开发会话 | 同一用户的工作区、外部会话引用 | 按实际开发任务管理 |
| RunContext | 用户、会话、工作区、绑定版本和当前实例 | 一次有效运行 |
| 沙箱实例 | 当前挂载的工作区 PVC | 可过期、销毁、替换 |
| PVC | 平台工作区及其 owner | 独立长期保留 |

长期配置不绑定 Pod 名称、IP 或某个 sandboxId。
再次使用时由平台创建或复用实例，并返回 RunContext。
每次工具调用显式携带该上下文。禁止使用共享全局“当前沙箱”。

建议本地保存 `.olixops/local.json`，并加入 Git 忽略。
其中只存个人资源绑定和凭证配置名，不存 Token。
平台地址固定在受信任的客户端配置中，变更时重新授权。
仓库内配置不能自动将凭证发送到任意服务器。

本地路径只作为客户端定位信息，不能作为服务端授权依据。
每次连接都核对当前账号与绑定资源的归属。
多个项目、Git worktree 或并发会话要明确各自的目标。
同一工作区的执行独占沿用现有规则。

MCP 不保证提供各工具统一的真实聊天 ID。
支持客户端集成时使用其稳定会话引用。
否则生成本地开发会话 ID，并允许用户恢复或新建。
它只是外部引用，不能被描述为自动同步的聊天记录。
当前规范已弃用 Roots，新设计也不依赖它自动发现目录。

[当前 MCP Roots 边界](https://modelcontextprotocol.io/specification/2026-07-28/client/roots)

## C 用户如何关联和使用

1. 在本地工具中登录平台。
2. 选择当前项目和自己的工作区。
3. 保存当前目录的关联信息。
4. 在 AI 客户端添加平台 MCP。
5. 调用准备工具，获得 RunContext。
6. 同步代码，再执行和验证应用。

再次打开目录时，工具加载已有关联。
实例仍可用则复用，已销毁则挂载原 PVC 重建。
平台显示当前工作区、实例和代码同步版本。

MCP 不会自动读取用户电脑上的任意目录。
远端服务收到本地路径，也无法据此读取本地文件。
需要客户端把内容传上来，或由受限的本地同步工具上传。
不要求用户一直打开平台网页，也无需用户手工管理 Pod。

## D 登录、工具授权和资源权限

目标方案：远程 MCP 使用 OAuth 授权码与 PKCE。
公司 IdP 通过 OIDC 提供登录身份。
API 使用面向 MCP 资源的 access token，不能拿 ID token 代替。
MCP 端校验签发者、接收方、有效期与授予范围。
登录完成不代表有权操作任意工作区。

[MCP 官方授权规范](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization)
[OIDC 身份规范](https://openid.net/specs/openid-connect-core-1_0.html)

当前仍是本地账号登录，可先增加独立的个人工具凭证。
个人访问令牌需要有效期、撤销、作用域和资源范围。
令牌只展示一次，服务端保存摘要，客户端存系统凭证库。
不要复制网页会话 Token 当作长期 MCP 配置。

PAT 是过渡方案，不等于完成标准 MCP OAuth。
远程客户端须明确支持自定义认证头才可直连。
否则使用 stdio 适配器，由它携带 PAT 调平台 HTTPS API。
本地适配器仍按当前用户授权，不能内置共享管理密钥。

建议权限按三者交集计算：

- 用户当前的项目和资源权限。
- 此次客户端授权的工作区和操作范围。
- 当前 RunContext 的资源和状态约束。

统一业务/API 层必须执行这三项检查。
不能只在 MCP tools/list 中隐藏工具。
也不能让同一个受限 Token 绕回 REST API 获得更大权限。

任意命令执行意味着能修改该沙箱内的数据。
因此只读凭证不能同时允许不受限的 exec 工具。
CLI 账号停用、令牌撤销或项目权限变化后，新请求要拒绝。
已经提交的后台进程不因令牌撤销自动停止。
紧急停用还需要停止相关计算实例。

OpenSandbox 的服务凭据只保留在平台后端。
用户 Token 不传给 OpenSandbox，也不注入沙箱环境。
公司入口使用 HTTPS，并修复证书链信任。

当前角色模型允许 owner/maintainer 管理同项目资源。
普通 member 仅能操作自己的资源。
若要求私人工作区对项目管理员也不可见，需新增私有规则。
默认给 AI 的授权应缩小到明确选择的工作区。

## E 本地代码与持久文件如何配合

建议首版采用“本地源码为主，显式同步到沙箱”。
AI 在本地修改文件，上传完成后再启动远端验证。
运行产物、日志和缓存可以保留在工作区。
远端修改过的源码需要显式拉取或处理冲突。
首版不做无提示的双向覆盖或同步删除。

同步工具需要记录文件清单、内容摘要和 revision。
执行记录引用同步版本，便于说明实际验证了哪些代码。
上传期间不启动依赖未完成文件的新验证任务。
运行中的应用如何切换代码，后续按运行管理规则处理。

默认排除 `.env`、密钥、`.git` 和依赖缓存。
凭据通过平台的受控配置提供，不随源码上传。
本地工具验证目录边界，不跟随越界符号链接。
批量上传服务要校验路径和大小，防止解包越界。
现有单文件接口限制 4 MiB，完整项目同步需要另外设计。

## F MCP 第一版工具范围

以下是建议工具名，并非已经实现的接口。

| 能力 | 建议工具 | 约束 |
|---|---|---|
| 查看关联 | context_get、workspace_list | 仅返回当前凭证可见资源 |
| 准备运行 | runtime_prepare、runtime_status | 复用现有准备任务和幂等规则 |
| 文件操作 | file_read、file_write、files_list | 每次检查固定 RunContext |
| 本地上传 | sync_push | 由本地助手读取受授权目录 |
| 命令与日志 | command_run、command_status、command_logs | 返回命令 ID，支持后续核对 |
| 应用验证 | http_check | 只访问被授权沙箱内的指定端口 |
| 结束运行 | runtime_release | 使上下文失效，保留工作区 |

有写入副作用的工具不能在网络超时后直接重放。
继续运行可复用现有 requestKey。
文件批次、命令等还需设计操作 ID、去重和状态查询。
不能把已有“创建幂等”误认为所有工具都幂等。

客户端可展示工具确认信息，但服务端权限仍是硬边界。
默认工具授权不包含成员管理、永久删除数据和发布上线。

## G 当前基础与待开发项

| 部分 | 当前情况 | 下一步 |
|---|---|---|
| 工作区、PVC、RunContext | 已实现 | 作为关联与执行基础 |
| 本地登录、项目角色、对象校验 | 已实现 | 提取可复用的统一授权入口 |
| 工具专用凭证和 scopes | 尚未实现 | 新增签发、撤销、范围和审计 |
| 本地目录关联 | 尚未实现 | 新增绑定文件和客户端命令 |
| 平台 MCP | 尚未实现 | 协议适配和客户端兼容测试 |
| 完整项目同步 | 尚未实现 | 显式上传、清单、冲突和限制 |
| 公司 OIDC / MCP OAuth | 尚未实现 | 对接公司身份系统与授权流程 |

首版建议使用受限 PAT 和本地 stdio 适配器。
先完成本地关联、受限工具调用和显式上传。
再接完整 OAuth/OIDC，扩展应用运行管理。
代码发布和镜像构建另开阶段。

已有授权有一部分位于 Gin handler。
MCP 若直接调用底层服务，不能跳过这些校验。
应让 REST 与 MCP 共用业务授权，而不是各写一套规则。

MCP 使用 JSON-RPC，不能套用业务接口的 code/msg/data。
实现前应记录协议端点例外，并保留 REST 现有契约。
协议版本和客户端能力要明确验证，不能假定全部客户端相同。
OIDC 身份以 issuer/sub 映射平台用户，保持已有数据 owner 稳定。

依据：`internal/domain/runtime.go`、`internal/interfaces/router/router.go`、
`internal/interfaces/middleware/auth.go` 和 `design/security.md`。

## H 验收与规范依据

- 本地项目关联后，重启 IDE 仍能恢复原工作区。
- 删除实例后，本地 AI 能在新实例中读到原文件。
- A 用户或受限令牌不能操作未获授权的工作区。
- 同一令牌直接调用 REST 也不能越过工具授权。
- 两个并发会话不会操作错工作区。
- 权限撤销后新请求被拒绝，已有进程行为有明确说明。
- 传输重试不会重复执行具有副作用的命令。
- 上传排除凭据，冲突不静默覆盖，操作可关联到 revision。

规范核对日期为 2026-11-06。
官方 latest 当前指向 2026-07-28；实际客户端可能使用旧版本。
新版状态 handle、旧版会话 ID 都不能作为用户身份或工作区绑定。
